DLL 注入器

一个带图形界面的 Windows 工具：选择目标 exe 与要注入的 dll，一键「挂起启动 → 注入 → 恢复运行」。也支持向运行中的进程直接注入、卸载已注入的 DLL，内置注入结果自动核验。

自包含单文件 · 免安装 .NET 运行时 · MIT License

Features

功能特性

从启动时注入到运行中进程管理，覆盖完整的注入 / 卸载闭环。

🎛️

图形界面

直观的 WinForms 界面，支持直接把文件拖拽进输入框（多文件一次拖入）。

🚀

启动时注入

以CREATE_SUSPENDED挂起方式启动目标 → 批量注入 DLL → 恢复主线程运行。

📦

多 DLL 批量注入 + 排序

DLL 输入框内用 ; 分隔多个 DLL，一次全部注入；「⇅ 排序」对话框支持拖拽 / 上移 / 下移调整注入顺序。

🖥️

注入到运行中进程

刷新枚举进程（名称 + PID），选中后一键注入（OpenProcess + 远程 LoadLibraryW）。

🧩

注入后调用导出函数

注入成功后自动远程调用指定导出函数（如 InstallHook / Init）；可传单个字符串参数，或用 || 传多个参数（DLL 侧按字符串指针数组接收），并记录函数返回码。

📤

卸载已注入 DLL

远程调用 FreeLibrary 卸载，注入 / 卸载闭环；64 位进程基址完整枚举，卸载可靠。

✅

注入结果核验

注入后自动在目标进程模块列表核对 DLL 是否真正加载成功（带重试容忍枚举时序）。

🧬

三种注入方式

CreateRemoteThread（兼容）· NtCreateThreadEx（隐蔽）· QueueUserAPC（仅启动时）。

🖥️

x64 / x86 双架构

注入器按目标位数分版，位数自动校验，不匹配时拦截并给出清晰提示。

🛡️

自动 UAC 提权

非管理员启动自动弹出 UAC 提权；取消则按普通权限继续，注入普通进程无需提权。

💾

记忆上次选择

自动记住上次的 exe / dll（多 DLL 完整记忆）、注入方式与窗口位置，下次启动直接带出。

🌐

支持中文路径

DLL 路径以 UTF-16 写入远程进程，中文目录 / 文件名完全兼容。

⚙️

命令行模式

-inject / -injectpid / -eject，支持多 DLL、注入方式与 -export 导出函数调用，退出码明确区分成败。

Usage

快速上手

从 Releases 下载对应位数版本，把目标 exe / dll 与注入器放在同一目录即可使用。

1

启动时注入

启动目标程序并注入 DLL，适用于插件 / MOD / 调试等场景。

  1. 「目标程序」选择要启动的 exe
  2. 「DLL 文件」选择要注入的 dll（多个用 ; 分隔）
  3. （可选）填写「启动参数」
  4. （可选）填写「导出函数」（注入后要调用的函数名，如 InstallHook）与「调用参数」（单个字符串，或用 || 分隔多个参数）
  5. 选择「注入方式」→ 点击注入并启动
2

注入到运行中进程

向已运行的进程注入，无需重启目标程序。

  1. 点击「刷新」加载进程列表
  2. 下拉选择目标进程（名称 + PID）
  3. 点击注入到进程
3

卸载 DLL

把目标进程中已加载的 DLL 卸载掉，形成闭环。

  1. 在「DLL 文件」输入框填写模块名或路径
  2. 选择目标进程
  3. 点击卸载 DLL
# 命令行模式（自动化 / 脚本）
DllInjector-x64.exe -inject <exe路径> <dll1> [dll2 ...] [-args <参数>] [-method crt|ntc|apc] [-export <函数>] [-exportarg <参数>]
DllInjector-x64.exe -injectpid <pid> <dll1> [dll2 ...] [-method crt|ntc] [-export <函数>] [-exportarg <参数>]
DllInjector-x64.exe -eject <pid> <dll文件名>
How it works

注入原理

经典远程线程注入流程：进程外分配内存 → 写入 DLL 路径 → 远程加载 → 恢复运行 → 核验。

1 · CreateProcess以 CREATE_SUSPENDED 挂起启动目标不执行入口，主线程挂起
↓
2 · 远程内存VirtualAllocEx + WriteProcessMemory写入每个 DLL 的绝对路径（UTF-16，支持中文）
↓
3 · 远程加载CreateRemoteThread / NtCreateThreadEx / QueueUserAPC远程执行 LoadLibraryW，触发 DllMain
↓
4 · 等待完成WaitForSingleObject(15s)等待 DLL 初始化完成（APC 方式跳过，改为恢复后核验）
↓
5 · 恢复运行ResumeThread恢复目标进程主线程，程序正常运行
↓
6 · 核验模块列表检查确认每个 DLL 已出现在目标进程模块列表
Compare

注入方式对比

三种注入方式在不同场景下的适用性与特性差异。

方式启动时注入运行中进程特点
CreateRemoteThread ✔ ✔ 兼容性最好，最常见的注入手法，较易被检测
NtCreateThreadEx ✔ ✔ 直接调用 ntdll 底层线程创建，绕过部分 API 钩子，隐蔽性较好
QueueUserAPC ✔（推荐） ✘（自动降级 CRT） 不创建新线程，隐蔽性最好；要求目标主线程处于可告警等待，否则 APC 不会执行

Notice

注意事项

位数必须一致 — DLL 必须与目标程序同为 32 位或 64 位，否则会拒绝注入。
仅支持原生 DLL — 需为含 DllMain 的 C/C++ 编译产物，托管 .NET DLL 无法以此方式执行代码。
QueueUserAPC 局限 — 仅适用于启动时注入，且目标主线程需处于可告警等待，否则不会执行。
杀软可能告警 — CreateRemoteThread 注入是常见手法，部分杀毒软件会报毒。
请合法使用 — 仅对你有权操作的软件使用（插件、MOD、调试、内部工具等场景）。
